Reference instance

The public Bellows on Tinfoil Containers: its address, what it answers and what has run there.

On this page

  • What it answers
  • What it charges
  • What has run there
  • Use it

Release 0.2.0 runs sealed on Tinfoil Containers at this address. It takes real eCash. Check its build before you send it anything.

https://bellows.island-bitcoin.containers.tinfoil.dev

What it answers

Its public routes are free to read:

B=https://bellows.island-bitcoin.containers.tinfoil.dev
curl -s $B/healthz                 # liveness and the BTC/USD rate in use
curl -s $B/v1/models | jq '{units, mints, ids: [.data[].id]}'
curl -s $B/ohttp-keys | tail -c +3 | base64     # its Oblivious HTTP key

The models, prices and mints it offers can change. Read them from /v1/models each time.

What it charges

It charges the suppliers' cost with no margin: BELLOWS_MARKUP is 1 in its measured tinfoil-config.yml, and its operator pays its hosting. An instance you run yourself marks the cost up by 1.25 unless you set another markup.

Its default unit is sat: a request that names no unit is asked in sats. Send X-Forge-Unit: usd to pay in cents.

To check its prices, compare pricing.usd_per_mtok in /v1/models with the supplier's cost, input_usd_per_mtok and output_usd_per_mtok in config/models.json at the release tag it runs. A model whose supplier bills input from its prompt cache at a lower price also lists cached_input, to compare with cached_input_usd_per_mtok. At markup 1 they are equal. Prices in the configuration reference says more.

What has run there

  • Releases 0.1.0, 0.1.1, 0.1.2 and 0.2.0 were built and measured by the public release workflows, and each is listed in builds.json.
  • Checked on release 0.2.0 on 2026-11-21: /healthz answers through an attested request against ForgeReserve/bellows@v0.2.0; the identity document reports version 0.2.0; every model's listed price equals the catalog cost, cached input included; a chat request with no key and no unit gets a 402 quoted in sat, and one naming usd gets usd; the admin API refuses a request with no token.
  • /ohttp-keys answered on an earlier release and has not been read again on 0.2.0.
  • A paid request, an Oblivious HTTP round trip and reading a balance back after a restart are covered by the test suite and local runs. They have not yet been run on sealed hardware.

Not verified on sealed hardware lists every step that has not been checked there.

Use it

  • Check which build it runs before you send it a token.
  • Quickstart opens a balance and sends a chat request.
  • To run your own instance, follow the operator guide.
