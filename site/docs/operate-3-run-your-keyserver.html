3. Run your keyserver

Run the keyserver that releases your secrets only to an approved build.

Run Tinfoil's reference keyserver (github.com/tinfoilsh/keyserver) on your server, with its TLS certificate. Pin its image to a release; this kit was written against release v0.0.5 (its image tag has no v: ghcr.io/tinfoilsh/keyserver:0.0.5).

  • Copy deploy/keyserver/policy.example.yaml and fill it in. You add the approval for your first release in step 5.
  • Choose a backend: HashiCorp Vault, AWS Secrets Manager or a local file. For the file backend, copy deploy/keyserver/store.example.json, fill it in on the offline machine, move it to the server and chmod 600 it.
  • The keyserver must serve /challenge and /fetch directly at keyserver-url, without redirects.

The keyserver releases a secret only to an enclave whose fresh attestation proves it runs your repository at an approved tag and holds a certificate for your instance's domain. You run it, so you decide which release gets your secrets. That is also the known weak point: see Threat model.

NOT VERIFIED: the keyserver's release to a Bellows enclave, and every secret arriving as an environment variable.
