Handle errors

The error shape, and what to do about the codes an app meets most.

Every error is OpenAI-shaped: {"error": {"message", "type", "code"}}. Match on code.

curl -s $B/v1/chat/completions -H "authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"model": "no-such-model", "messages": [{"role": "user", "content": "Hello"}]}'
# {"error":{"message":"unknown model no-such-model; see GET /v1/models","type":"model_not_found","code":"model_not_found"}}

The ones an app meets most:

Status and codeWhat to do
402 payment_requiredPay: send the request again with X-Cashu for the amount in the body, or with a balance key
402 insufficient_balanceTop up the balance, or ask for fewer max_tokens
401 invalid_keyThe engine does not know this key. A key works only at the engine that issued it
404 model_not_foundPick a model from GET /v1/models
400 untrusted_mint, wrong_unit, insufficient_amount, invalid_tokenThe token was refused before any eCash moved. It is still yours to spend
400 token_spentThe mint reports the token as already spent
403 invite_requiredThe engine is invite only. Ask its operator for a code
428 pow_requiredSolve the proof of work and send the request again
429 rate_limitedWait Retry-After seconds
502 upstream_errorThe model failed. Nothing was charged and a per-request payment comes back whole as change
503 mint_unavailableSend the request again with the same token, or fetch its change at GET /v1/change/{request_id}
503 topup_pendingSend the topup again with the returned key and the same token

GET /v1/change/{request_id} answers 409 not_settled with Retry-After while the request still runs. The full list of codes is in API reference.
